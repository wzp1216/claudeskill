# 计划文件格式规范

计划文件是 normal-work 的唯一持久化真相。所有门户通知、会议、OA 邮件摘要与
计划项都落在当日 Markdown 中，不另建数据库。

## 位置与命名

- 固定目录：`/media/data/AAAwork/claude/normal-work/plan/`
- 文件名：`YYYY-MM-DD.md`（与 cwd 无关，绝对路径）
- 历史文件**永不修改**；完成/取消只改当日文件

## 计划项 schema

- **ID**：`T-YYYYMMDD-NN`，创建日 + 当日序号；滚动时沿用原 ID
- **状态标记**：`[ ]` 待办、`[x]` 完成、`[-]` 取消；延期 = 改截止日期 + 备注说明
- **字段**（`  - 字段名：值`，按序排列）：
  - 必填：优先级（高/中/低，默认中）、OA提醒状态
  - 选填：截止、涉及人员、来源、来源ID、链接、备注
  - 滚动专属：来源日（首次出现的日期）、滚动次数（每滚一天 +1）、原计划日（最近一次所在日期，与来源日不同才写）
- **OA提醒状态机**：`无需` → `未生成` → `草稿已生成` → `待确认` → `已发送 YYYY-MM-DD HH:MM`；异常：`待核实`、`失败：原因`

## 滚动算法（plan_manager.py rollover）

1. 扫描 plan/ 下最近 `--lookback`（默认 7）个自然日的文件（不含当日）
2. 按文件日期从旧到新解析所有计划项，同一 ID 以最新文件的状态为准
3. 最新状态为 `[ ]` 且当日文件中无相同 ID / 规范化标题的项 → 复制进"三、昨日未完成（滚动）"
4. 滚动次数 +1；保留来源日；若最新所在日期 ≠ 来源日，补写原计划日
5. `[x]`/`[-]` 不滚动；重复运行幂等（ID 已在当日则跳过）

## 生成块（block）与手工内容的分界

- "一、门户信息"和"二、OA 邮件摘要"是**生成块**（`<!-- normal-work:portal/oa:start/end -->` 标记包裹），每次刷新整体替换；块内内容不要手工编辑
- "三、四、五、六"是**用户区域**：脚本只做单条增改和清单刷新，绝不整文件重写，保留手工编辑
- 同日重跑：只替换生成块 + 按来源ID 去重新增建议项；不重复滚动

## 脚本操作约定

- 所有增删改通过 `scripts/plan_manager.py` 完成（原子写入 + 文件锁）
- 门户/OA 提取结果先写到 `tmp/` 下的内容文件，再用 `replace-block` 替换，避免长参数
- 计划项建议由 Claude 判断后逐条 `add`，必须带 `--source` 与 `--source-id`
- 来源ID 规则：页面提供的 ID 优先；否则用"来源类型+规范化标题"的 md5 前 12 位（如 `portal-` + hash），保证同日去重稳定
